# 项目级生成工作台设计

## 目标

将当前按场景独立触发的图片、配音和导出能力，提升为一个可恢复的项目级生产流程。用户在工作台完成参数确认后，点击一次“开始生成”，系统按场景顺序补齐所有缺失或过期素材；每个场景先生成旁白，再生成画面，并在完成过程中逐项回填时间线。

第一版使用项目内串行调度，后续可以在不改变前端状态协议和持久化结构的前提下增加有限并发。

## 已确认的产品规则

- 点击“开始生成”默认扫描并处理全部未完成场景。
- 已有有效素材的步骤跳过，只补齐缺失项。
- 旁白或画面提示词变化会使对应素材过期，下一次运行自动重建。
- 生成过程中只锁定当前场景，其他场景可以继续编辑。
- 等待中的场景修改不改变当前运行快照，进入下一轮运行。
- 单场景失败不阻断后续场景。
- 运行结束后支持“仅重试失败项”。
- 单个场景先生成旁白，再生成图片。
- 旁白完成后立即建立时间线片段并使用真实音频时长。
- 场景没有当前图片时，新图片自动成为当前版本。
- 场景已有当前图片时，新图片保存为候选版本，必须显式确认后才替换当前版本。
- 生成运行使用开始时的参数快照，不受运行中全局设置修改影响。
- 第一版项目内串行执行；以后再考虑项目内并发生产。

## 用户体验

### 空闲状态

工作台顶部显示项目标题、场景数量、待生成数量和候选待确认数量，并提供 `生成设置` 和 `开始生成`。生成设置展示图片模型、画布尺寸、TTS 模型、声音、语速、图片风格前缀、字幕、BGM 和模板。点击开始后，这些参数冻结为本次运行快照。若没有任何缺失或过期素材，显示无任务可生成，不重复消耗模型任务。

### 生成中状态

顶部显示总体进度、当前场景和 `暂停`、`取消` 操作。暂停表示当前请求完成后不再启动下一个场景；取消表示当前请求尽量完成，但剩余场景不再启动并标记为 `cancelled`。不强制中断外部模型请求。

当前场景的输入框和生成按钮锁定。其他场景保持可编辑。界面高亮当前场景，但不强制滚动，避免打断用户正在编辑的场景；提供“定位当前”作为主动跳转操作。

场景队列状态包括：`queued`、`running_tts`、`running_image`、`completed`、`skipped`、`failed`、`cancelled`、`candidate_review`。

### 时间线回填

1. TTS 完成后得到真实音频时长。
2. 立即创建或更新该场景片段。
3. 图片完成后填充画面缩略图。
4. 有旧当前图片时，保留旧图并显示新候选标记。
5. 用户确认候选后，时间线切换到新版本。

时间线片段使用稳定尺寸约束，等待中和生成中的场景不能导致其他片段跳动。

### 运行结束

成功完成时显示成功、跳过和候选待确认统计，并提供继续编辑和导出入口。有失败时显示失败原因和“仅重试失败项”。有未确认候选时，项目进入待审核状态；导出对话框提醒用户，默认仍使用当前确认版本，不自动切换到候选。

## 运行模型

### GenerationRun

一次项目级生产运行，建议持久化以下字段：

```text
run_id
project_id
status
parameter_snapshot
current_scene_id
total_count
completed_count
skipped_count
failed_count
pause_requested
cancel_requested
created_at
updated_at
```

运行状态至少包括 `queued`、`running`、`paused`、`completed`、`completed_with_failures`、`cancelled` 和 `failed`。

### GenerationRunItem

一个场景在某次运行中的不可变执行计划：

```text
run_id
scene_id
position
narration_snapshot
prompt_snapshot
narration_fingerprint
image_fingerprint
tts_status
image_status
status
error
created_at
updated_at
```

音频和图片分别计算指纹：

```text
音频指纹 = 旁白文本 + 语音配置 + 语速 + TTS 模型
图片指纹 = 画面提示词 + 图片模型 + 画布尺寸 + 风格参数
```

指纹未变化且当前素材存在时跳过对应步骤。旁白变化不导致图片无意义重建，提示词变化也不导致音频重建。

现有 `GenerationJob` 继续表示一次具体的 TTS、图片或导出任务；项目级运行作为父级编排记录，通过 `run_id` 关联子任务。

## 执行流程

```text
创建 GenerationRun
  ↓
扫描场景并生成 GenerationRunItem
  ↓
按 position 顺序取下一个未完成项
  ↓
检查音频指纹
  ├─ 有效 → skipped
  └─ 缺失/过期 → 创建 TTS 子任务
          ↓
      写入音频与真实时长
          ↓
      建立时间线片段
          ↓
      检查图片指纹
      ├─ 有效 → skipped
      └─ 缺失/过期 → 创建图片子任务
              ↓
          无当前图：自动选择新版本
          有当前图：保存候选版本
              ↓
          更新场景和运行项状态
              ↓
          继续下一个场景
```

运行过程中服务重启后，恢复未完成的运行。当前外部请求不做强制中断，避免产生半成品；暂停和取消采用协作式调度。

## API 草案

```text
POST /api/projects/{project_id}/generation-runs
GET  /api/projects/{project_id}/generation-runs/{run_id}
POST /api/projects/{project_id}/generation-runs/{run_id}/pause
POST /api/projects/{project_id}/generation-runs/{run_id}/resume
POST /api/projects/{project_id}/generation-runs/{run_id}/cancel
POST /api/projects/{project_id}/generation-runs/{run_id}/retry-failed
```

创建接口返回 `runId`。查询接口返回总体计数、当前场景、运行项状态、错误信息、候选待确认数量和最近更新时间。第一版前端每秒轮询；后续可将同一响应模型迁移到 SSE 或 WebSocket。

同一项目已有活动运行时，创建接口返回冲突和现有 `runId`，避免重复启动。

## 错误与恢复

- 单场景异常转换为运行项失败并继续调度。
- 记录外部服务超时、下载失败、音频解析失败等可读错误。
- 不自动无限重试；失败项通过新运行手动重试。
- 当前版本、候选版本和音频文件不互相覆盖。
- 取消后的剩余项标记为 `cancelled`，恢复时从第一个未完成项继续。
- 场景编辑使用内容指纹或版本检查，避免运行快照覆盖用户新编辑。
- 导出继续使用不可变快照和现有导出前置检查。

## 实施阶段

1. **运行模型**：SQLite 表、模型、repository、状态转换、指纹计算。
2. **后端调度器**：串行 TTS/图片编排、跳过逻辑、候选版本、失败继续、暂停、取消和恢复。
3. **API**：运行创建、查询、控制和失败重试接口。
4. **前端工作台**：顶部生成控制、运行状态、场景队列、轮询、时间线增量回填和候选审核。
5. **测试验收**：模型状态、指纹规划、顺序调度、失败继续、控制恢复、API 契约、前端状态和浏览器流程。

## 第一版范围外

- 项目内并发生产。
- WebSocket/SSE 实时推送。
- 自动重试策略。
- 多轨时间线。
- 跨项目素材库。
- 多用户协作和权限。
