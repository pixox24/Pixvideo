    AI 剪辑工作台设计¶

    状态¶

    设计已通过逐段讨论，等待用户审阅书面规格。本文档描述首期产品边界和实现方向，不包含实现代码。

    1. 背景与目标¶

    PixVideo 当前的核心路径是快捷创作：用户输入主题或脚本，系统生成旁白、分镜提示词、图片/视频素材、字幕和成片。下一阶段将把它扩展为一个面向工作室操作员的 AI 剪辑工作台。

    工作台的核心任务不是替代 Premiere 或剪映，而是让用户在初稿生成后快速完成以下闭环：

    1. 查看长项目中的分镜和预览。
    2. 找到不满意的画面。
    3. 编辑该分镜的画面提示词，或替换为项目内上传素材。
    4. 生成并比较候选版本，确认后替换当前画面。
    5. 调整分镜顺序和画面停留时长。
    6. 在不重新生成整片的情况下导出最终视频。

    首期目标用户是工作室中的单个操作员，典型项目超过 3 分钟、包含 30 个以上分镜，在单台 Windows 工作站的本地浏览器中使用。

    2. 已确认的产品决策¶

    • 快捷创作和工作台属于同一个项目生命周期，不做两个互相割裂的产品。
    • 快捷创作默认生成初稿并打开工作台，同时保留“直接生成成片”旁路。
    • 工作台首期是“AI 分镜精修台”，不是完整多轨剪辑器。
    • 首期支持 AI 生成素材和项目内临时上传素材；暂不建设跨项目素材库。
    • 初稿创建后立即进入工作台，图片和音频按分镜渐进生成。
    • 每次生成或上传都保留为素材版本；新候选不会自动替换用户正在使用的画面。
    • 不引入团队账号、权限、审批状态或实时协作。
    • 不增加“未审/需修改/已通过”等业务状态；仅展示排队、生成中、已完成、失败等技术状态。
    • 首期支持单镜旁白编辑，只重新生成当前分镜的 TTS 和字幕时间，不重新切分整篇。
    • 首期支持轻量批量操作：批量应用提示词前缀/风格约束和批量提交图片生成。
    • 默认时长由当前分镜的 TTS 音频决定；用户可以延长画面停留，但不能把画面裁短到旁白播放不完。
    • 导出使用不可变快照，复用现有 FFmpeg、模板、字幕和 BGM 合成链路。

    3. 方案比较¶

    方案 A：同一项目的两个阶段（采用）¶

    快捷创作负责建立项目和初稿，工作台负责精修和导出。两者共享项目、分镜、素材版本和配置快照。

    优点是路径自然、状态只有一份、适合渐进生成和局部重生成；代价是需要从“一个视频任务”扩展出真正的项目和分镜模型。

    方案 B：生成完成后导入编辑器¶

    保留现有任务结构，完成后复制结果成为编辑项目。短期改动较小，但会产生任务和项目两套数据、重复文件和恢复逻辑，不作为长期架构。

    方案 C：工作台完全取代快捷创作¶

    所有配置、生成和编辑都在一个大界面完成。入口看起来统一，但会让长表单、素材区、预览和时间线互相争夺空间，损害一键创作效率，不采用。

    4. 用户体验设计¶

    4.1 创建初稿¶

    快捷创作提交时先创建本地项目和分镜草稿，并保存本次生成配置的快照。配置快照包含画幅、工作流、模型、声音、字幕、BGM 和模板等决定成片结果的参数。

    默认 CTA 是“生成初稿并打开工作台”；“直接生成成片”保留为次要操作。项目创建成功后，工作台立即显示所有分镜，图片、TTS 和其他媒体按队列逐个填充。

    4.2 首屏布局：三栏精修台¶

    • 顶部栏：项目名、自动保存状态、撤销/重做入口、导出。
    • 左栏：分镜 与 素材 标签。分镜列表使用可滚动/虚拟化列表，显示缩略图、编号、简短旁白和技术状态；素材标签显示项目内可用图片。
    • 中央区：当前分镜的大画面预览，支持播放、暂停、前后分镜切换和适配画布的缩放。
    • 右栏：当前分镜检查器，包含旁白、画面提示词、候选版本和重新生成操作。
    • 底部：顺序、时长和整片播放控制。时间线是单个视频轨的轻量编辑器，不承担多轨合成。

    对于 30–100 个分镜，左栏是主要定位工具，底部时间线只承担连续性和节奏调整，不要求用户靠一行缩略图寻找远处镜头。

    4.3 单镜精修¶

    点击左栏分镜后，预览、检查器和时间线同步切换到该镜头。

    提示词修改会自动保存为草稿；只有点击“重新生成”才创建新的图片任务。任务使用点击时的提示词快照，之后继续编辑不会改变已提交任务。

    候选图完成后，在检查器中显示版本编号、生成时间、来源和对比操作。用户可以放大查看候选，点击“使用此版本”后才更新当前画面。当前版本始终保留，直到用户明确选择替换。

    本地上传素材复制到项目目录并创建一个素材版本，与 AI 生成候选使用同一套预览和确认操作。

    4.4 旁白编辑与时长¶

    旁白只属于当前分镜。保存后重新生成该镜 TTS，重新计算该镜字幕时间和最小时长；其他分镜、画面提示词和顺序不变。

    分镜默认时长取当前 TTS 音频时长。用户可以在时间线上延长画面停留，不能把画面裁短到旁白播放不完；需要缩短时编辑旁白或调整语速配置。

    4.5 批量操作¶

    左栏支持多选。多选后显示批量工具栏：

    • 应用统一提示词前缀、风格描述或负面约束。
    • 为选中的分镜批量提交图片重生成。
    • 查看批次进度并取消单个分镜。

    批量结果仍分别创建候选版本，不自动替换当前画面。首期不支持批量修改旁白或批量调整时长。

    4.6 导出¶

    导出前显示确认面板，包括分镜数量、总时长、画幅、当前版本、字幕、BGM 以及尚未完成的素材。

    仍有生成中、缺少图片或缺少音频时默认阻止导出，并定位到具体分镜。允许用户显式选择“只导出当前已完成版本”，但需要二次确认。

    确认后创建不可变的 ExportRevision，再调用现有合成链路。导出期间继续编辑不会影响正在生成的文件。

    5. 数据模型与持久化¶

    5.1 Project¶

    保存项目 ID、名称、创建/更新时间、来源（快捷创作或历史任务恢复）、配置快照、当前导出记录和素材根目录。

    5.2 Scene¶

    保存分镜 ID、所属项目、顺序、旁白文本、画面提示词、当前素材版本 ID、音频路径、字幕对齐信息、时长和技术状态。

    5.3 AssetVersion¶

    保存版本 ID、所属分镜或项目素材池、来源（AI/上传）、文件路径、缩略图路径、生成提示词快照、生成参数、创建时间和可用性。版本是追加记录，当前选择通过 current_version_id 表示。

    5.4 GenerationJob¶

    保存任务 ID、项目/分镜引用、任务类型（TTS、图片、批量图片、导出）、输入快照、后端任务 ID、状态、进度、错误信息和产物引用。每个分镜可独立重试或取消。

    5.5 ExportRevision¶

    保存导出 ID、项目引用、导出时的分镜顺序与时长、每个分镜选中的素材版本、音频/字幕/BGM 配置、输出路径、状态和错误信息。它是可重试导出的完整输入，不随项目后续编辑变化。

    5.6 存储策略¶

    首期采用本地优先：SQLite 保存结构化项目状态，项目目录保存原图、缩略图、音频、临时合成文件和最终视频。媒体路径只保存为项目内相对路径，避免把临时绝对路径直接暴露给前端。

    现有按任务划分的 metadata.json 和 storyboard.json 继续兼容历史任务。打开历史任务时可以只读展示，用户选择“继续精修”时再建立项目快照；不要求一次性迁移所有旧输出。

    6. API 与组件边界¶

    后端新增项目域接口，沿用当前 FastAPI 路由和 TaskManager：

    • POST /api/projects：从快捷创作输入创建项目和分镜草稿。
    • GET/PATCH /api/projects/{project_id}：读取和保存项目元数据、全局顺序和配置。
    • GET/PATCH /api/projects/{project_id}/scenes/{scene_id}：保存旁白、提示词、时长和顺序。
    • POST /api/projects/{project_id}/scenes/{scene_id}/image-generations：创建单镜图片候选任务。
    • POST /api/projects/{project_id}/scenes/{scene_id}/uploads：上传并登记项目内素材版本。
    • POST /api/projects/{project_id}/scenes/{scene_id}/versions/{version_id}/select：确认当前版本。
    • POST /api/projects/{project_id}/batch/image-generations：提交批量图片任务。
    • POST /api/projects/{project_id}/exports：从导出快照创建合成任务。

    前端组件边界建议保持清晰：ProjectWorkbench 负责布局和选中分镜；SceneList 负责长列表和多选；SceneInspector 负责旁白/提示词/版本；Timeline 负责顺序与时长；GenerationQueue 负责任务进度；ExportDialog 负责导出检查和提交。现有 QuickCreate 继续负责初稿配置，不把时间线逻辑塞入其中。

    7. 错误与恢复¶

    • 单镜生成失败不阻塞其他分镜，保留当前有效版本并提供重试。
    • 任务取消是正常终态；前端显示取消而不是失败。
    • 上传失败不创建半成品版本；临时文件在任务结束后清理。
    • 自动保存使用版本号或更新时间检查，避免异步任务回写覆盖用户刚保存的提示词。
    • 导出失败保留 ExportRevision，支持原输入重试。
    • 应用重启后从 SQLite 和项目目录恢复项目、候选版本和任务状态；无法访问的文件显示明确路径错误。

    8. 首期明确不做¶

    • 多用户账号、权限、评论、审批和实时协作。
    • 完整多轨时间线、转场、关键帧、滤镜和任意音视频叠加。
    • 跨项目素材库、标签体系和搜索服务。
    • 批量旁白重写、整篇自动重新切分和自动重排分镜。
    • 重新实现现有 TTS、字幕渲染、模板渲染和媒体工作流供应商。
    • 为每次画面修改自动导出整片。

    9. 验收与测试策略¶

    后端¶

    • 项目、分镜、素材版本、生成任务和导出快照的 schema 校验。
    • 新候选不会覆盖 current_version_id；选择版本后才更新引用。
    • 任务状态、取消、重试和导出快照恢复测试。
    • 上传文件的类型、路径隔离、缩略图生成和失败清理测试。
    • 旧 metadata.json/storyboard.json 历史任务兼容读取测试。

    前端¶

    • 快捷创作默认进入工作台，直接成片旁路保持可用。
    • 30+ 分镜列表滚动、选中同步、批量选择和候选确认行为测试。
    • 提示词自动保存、提交快照、单镜 TTS 更新和时长约束测试。
    • 生成中/失败/取消状态的局部更新，不影响其他分镜。
    • 导出检查面板阻止不完整导出，确认后提交不可变快照。

    浏览器回归¶

    • 桌面宽屏验证三栏布局、时间线拖动和右侧检查器不互相遮挡。
    • 窄屏至少验证：侧栏可收起、检查器可抽屉化、导出和关键操作仍可访问。
    • 使用 mock 任务状态验证渐进生成、局部失败恢复和项目重载，不触发真实付费生成。

    10. 成功标准¶

    一个包含 30–100 个分镜的项目可以从快捷创作进入工作台，素材渐进填充；操作员能够只重做一个不满意的画面、比较并确认候选、调整顺序和可延长的画面时长，最后在不重新生成其他分镜的情况下导出视频。关闭并重新打开应用后，项目、当前版本、候选版本和导出任务都可恢复。
